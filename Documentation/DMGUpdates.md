# DMG installation and Sparkle updates

The direct-download build uses Sparkle 2.10.1, with signed feeds and archive
verification before extraction. Automatic installation is off. Sparkle asks
whether to check automatically; Check for Updates is also in the app menu.

## Hosting and versioning

DMG layout is generated by create-dmg 8.1.0 (build-only Node 22 tooling), pinned
in Tools/dmg/package-lock.json. Run npm ci via Tools/build-dmg.sh; native build
dependencies require Xcode Command Line Tools. The wrapper performs signing
itself and refuses to overwrite existing artifacts.

Dependency audit: create-dmg/appdmg transitively use image-size 0.7.4, affected
by GHSA-w3rx-r6r6-pgpr (ICNS parsing infinite loop). npm reports three high entries
for the one transitive issue. appdmg's sizeOf call here reads only create-dmg's
pinned bundled PNG background; no user-controlled image is supplied. Tooling is
not bundled in Lunamo. Keep this limitation visible and reassess upstream before
adding custom image inputs. A blind override to image-size 2 breaks the callback
API used by appdmg and is not applied.

Feed: https://github.com/mani1261790/Lunamo/releases/latest/download/appcast.xml

Each public, non-prerelease release must include the versioned DMG and generated
`appcast.xml`. Downloads use immutable release-tag URLs. Never edit the signed
feed or replace an existing version's DMG. Increase CFBundleVersion for every
update, and CFBundleShortVersionString for the public version.

Until the first release is published, Check for Updates encounters a missing
feed. A successful build does not prove the hosted update channel works.

## Keys and release commands

The Sparkle Ed25519 key is separate from Apple signing. Its private key is in
the login Keychain, account `dev.marimonative.app`; only the public key is in
Info.plist. Back up the private key securely; never commit it or log it.
CI additionally requires `SPARKLE_PRIVATE_KEY` containing the exported key.

Set MARIMONATIVE_CODESIGN_IDENTITY to the Developer ID Application identity,
and MARIMONATIVE_NOTARY_PROFILE to your notarytool Keychain profile (or use the
existing Notary API key environment variables).

```sh
./Tools/build-release-app.sh
./Tools/notarize-release.sh
./Tools/build-dmg.sh
./Tools/notarize-dmg.sh .build/release-artifacts/Lunamo-0.1.0.dmg
./Tools/generate-update-feed.sh .build/release-artifacts/Lunamo-0.1.0.dmg v0.1.0
```

Use the actual version/tag for subsequent releases. The updates directory
contains the DMG and signed feed to publish together. Neither these commands
nor the GitHub workflow publish a release. Both app and DMG notarization must
succeed before feed generation. Existing DMGs are never overwritten.

For a local preview use `Tools/build-dmg.sh PATH/TO/Lunamo.app development`.
The resulting `-development.dmg` is not a notarized release and cannot be used
by the production feed generator.
